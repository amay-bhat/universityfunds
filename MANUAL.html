01What you are operating

Two machines stacked on each other. The work plane reads a ledger and gets tasks done. The decision plane handles the questions that come up while doing them. You sit above both.

PartWhat it isWhere it lives
LedgerThe plan and the memory. Tasks, checkboxes, leases, and the build log where every decision is recorded.TASKS.md
ConductorReads the ledger, splits work into briefs, routes each to a model tier, verifies the results, merges them, logs it. Never writes product code itself..claude/skills/conduct/
ChainWhen a session hits a real fork, it answers the question itself, then a fresh agent one tier up rules on it blind. Sonnet → Opus → Fable → you..claude/skills/escalate/
KernelThe rules that bind every session: six universal articles, and the list of powers reserved to you. Signed 30 July 2026.escalate/references/kernel.md
GatesCheckpoints A and B. The line stops; you review. Not escalatable — no model may route around them.TASKS.md
The one rule that makes it safe

The conductor is disposable; the ledger is not. Kill any session at any moment and a fresh one reads TASKS.md plus conduct/plans/ and picks up where it left off. Nothing important lives in a session’s head. That is why interrupting is nearly always safe — see §8.

Two documents describe state rather than procedure, and they are rendered from the ledger, never authored beside it: the status page (live progress, republished at each integration) and the design document (why the framework is shaped this way). If either ever disagrees with TASKS.md, the ledger is right and the other is stale.

02The daily loop

cd ~/Projects/dashboardProject && claude
/conduct

That is the whole normal path. The conductor claims the next unblocked task, decomposes it, routes each piece, spawns workers, re-runs their acceptance checks itself, merges, updates the ledger, and republishes the status page. It stops on its own at exactly three things: a gate, a reserved matter, or budget exhaustion.

Before you type it, four checks

Not ceremony — two sessions once collided on this repo and it resolved by luck, not design.

grep -n "claimed-by" TASKS.md   # live leases. Only the convention line = nothing claimed
ls conduct/briefs/              # units dispatched but maybe unmerged
git status --short              # anything in flight
npm run seed:dry                # the data fingerprint (see §4)

Open every session by pointing it at its own rules

Do not skip this

A session’s auto-loaded instructions can be a cached older copy that omits the governance entirely — no constitution in the reading order, no escalation rule, no concurrency rule. A session that never learns the rules exist cannot follow them. Start with: “Read CONSTITUTION.md and .claude/skills/escalate/references/kernel.md before anything else.”

Bounded runs

InvocationBehaviour
/conductRun the next unblocked work until a stopping condition.
/conduct planDecompose only. Produces briefs, spends no worker tokens. Use this whenever you want to see the plan before paying for it.
/conduct 1.7That task and only that task, then stop.
/conduct until checkpoint-aRun through as many tasks as fit, halting at the gate.
/escalateForce a question onto the record through the blind two-phase chain. Sessions fire this automatically; you rarely need it.
Never in this repo

/conduct init scaffolds a fresh repo — it would overwrite CONSTITUTION.md and TASKS.md, the two files the reserved list exists to protect.

03Command reference

Every row below was run on 31 July 2026 except the two marked not run, which are destructive by design.

CommandDoesExpect
npm run seed:dry Validate data/ and stop. No database connection at all — works with no credentials. Validation passed (10 warning(s))
npm run seed:verify Run the validator against 30 deliberately-broken copies of data/ and assert each rule fires. Copies live in a temp dir; your files are untouched. 30/30 validator checks passed.
npm run seed Not run here. Validates, then writes to the production database — the --write flag is inside the npm script. One batched transaction. It prunes: rows absent from data/ get deleted. applied N statement(s) in one transaction
npx tsc --noEmit Typecheck. Note scripts/ is inside the compile scope, so a type error there breaks the Vercel deploy. Silence, exit 0
npm run lint ESLint over 12 real files (verified it is not silently linting nothing). Silence, exit 0
npm run build Production build; also runs TypeScript and reads .env.local. ✓ Compiled successfully, routes / and /_not-found only
npm run dev Local server for eyeballing the app. Starter page today — Phase 2 hasn’t built the shell yet
npm run db:push Not run here. Mutates the live schema. Also hangs on its interactive rename prompt in a non-interactive shell — column renames need hand DDL in one transaction. Only for a deliberate schema change; re-run after as a verifier expecting No changes detected
The three that bite

1. npm run seed --dry-run is not a safe command. npm swallows the flag; historically this performed the destructive write. A guard now catches it, but the command you want is npm run seed:dry.

2. npm run db:migrate / db:generate are a dead path. There is no committed migration history. db:generate would invent one; db:migrate then emits bare CREATE TABLE against a populated database and fails. The sanctioned route is db:push or hand DDL.

3. npm run db:studio can edit rows — writing to the database directly is flatly forbidden by Article 8. Read the seed files instead.

Also true

npm audit is registry-live: its count moves on its own, with no change to this repo and no change to the lockfile. So re-derive it — run npm audit — rather than trusting a number printed here. It read 10 findings (4 moderate, 6 high) on 2026-08-29, having read 16 when this page was written. Nothing is currently reachable at runtime: what would put sharp on the request path is next/image’s optimizer, and this site never routes an image through it — the SVG icon and the build-time OG card both bypass it. That is a property of how the site currently uses images, not a guarantee. npm audit fix --force installs Next.js 9 and destroys the app. The leave-it-alone decision is deliberate and logged.

Read the counts, not just the pass

128 endowment return row(s), 130 benchmark return row(s), 0 proxy mapping(s)

A change in that line means someone edited data/. Verified in the files; the database matched at the last integration.

Read the warning set, not just the count

All ten are expected: seven are “category has no ETF proxy mapping yet (task 1.7)” — one per category actually in use, and note other is used by nobody — and three are empty benchmark series (global_equity, hedge_fund_index, public_pe_index). An eleventh warning is new and real.

This baseline expires

Task 1.7 populates the proxy table and at least one of the empty series, so the seven mapping warnings should go to zero and global_equity should clear. Whoever integrates 1.7 must record the new expected warning count in the build log, or no later session will know what green looks like.

Two supporting rules worth internalising: seed:verify must stay at full count because that is how an unauthorised edit to a validator file gets detected, and seed:dry is re-run after any write to prove the write was idempotent.

05Decisions only you can make

Three are open right now.

YoursTurn off Vercel Deployment Protectiontask 6.4

Settings → Deployment Protection → Vercel Authentication: Disabled, Production. Until then every logged-out visitor is redirected to a login and the site carries noindex — which contradicts the project’s headline “free, public, no-login” requirement.

Verify with no bypass header and no Vercel cookie: curl -I https://universityfunds-amay-s-projects3.vercel.app must return 200, not a 302 to vercel.com/sso-api. Use that long hostname; the short universityfunds.vercel.app is a different alias and 404s, which reads misleadingly like a broken deploy.

Not the same thing

“Protection Bypass for Automation” makes an automated curl return 200 while real visitors still hit the login — a green check over a broken requirement. Disable the authentication itself.

YoursCheckpoint A — what does v1 mean?one question, three parts

The plan asks for allocation charts spanning FY2000–FY2025 for all five schools. No school discloses that much, and each falls short differently:

  • Yale — 21 allocation years; stopped publishing after FY2020.
  • Harvard — 14 allocation years, and FY2005–FY2016 are published targets, not holdings.
  • MIT — 7 scattered years, three of them on a pool basis rather than the endowment itself.
  • Stanford — zero. Its percentages exist only for a pool that is ~73% endowment, with a measured 2.9-point return divergence.
  • Princeton — 18 years, with FY2019 and FY2024–25 missing.

Bless that as v1 or override it. Nothing is wasted either way — every school is curated to its real disclosure limit. Also on the agenda: acknowledge the citation-split telemetry (3 mixed-provenance years, all MIT), and rule on the congressional-responses lead below.

Write the answer down

Record it as a [HITL] entry in the build log. A verbal blessing leaves Checkpoint B with no standard to measure against, and leaves the page-building tasks inventing a Stanford policy that is itself the reserved call. Only you may amend PRD.md — it was deliberately left unamended precisely because this question is yours.

YoursPushre-derive the count

Pushing auto-deploys, so it stays your call. How much is waiting is a live number, not a fact this page can hold — run git rev-list --count origin/main..HEAD. This page asserted “3 commits local” long after the real answer had moved twice, which is exactly why it now names the command instead of an answer. When the count is non-zero, weigh what only one machine holds: rulings and curated data points are not recoverable from a redeploy.

One optional call that could change the picture

Every one of these schools answered the same two congressional endowment inquiries — and those responses are where MIT’s only allocation tables came from. Authorising a scoped research unit on them is the single lead that could turn Stanford from zero years into a series. The re-opening test is already written and must not be re-argued: at least 95% of the endowment held inside the pool — endowment-in-pool, not the pool’s endowment share.

06Never let a session do this

The reserved list, in operator terms. No model tier may approve any of it, however sound its reasoning, and there is no timeout that defaults past one — a reserved question always ends with “I stop here.”

ReservedMeans in practice
MoneySpending, plan changes, paid data subscriptions. Licensing a hedge-fund index would hit this and the licensing clause — relevant to task 1.7.
Irreversible or outward-facingForce-push, history rewrite, deleting branches/repos/production data, making anything public, publishing under the project’s name, messaging third parties.
SecretsRotating, moving, or committing credentials.
Legal postureThe site-level not-financial-advice wording, terms, data licensing. A session may draft the disclaimer; only you settle it.
Amending the rulesThe kernel, any constitution — including adopting one. A session may propose in the log; you adopt.
Product identityWhat v1 means, which schools are in scope, the name, the visual identity. This is why PRD.md stays unamended before Checkpoint A.
Anything marked [H]Dashboard clicks and account actions.

A plain git push is not literally enumerated, but because it deploys, the working rule is: the operator pushes; a session asks.

If a session asks you one of these

That is the system working correctly. Answer it, and the answer goes in the log.

Two data rules that outrank convenience

  • A gap stays a gap. Every school is curated to its real disclosure limit. Never let a session close one with a derived, interpolated, or wrong-universe number. That is the exact failure the validator, the coverage rule and three separate rulings exist to prevent.
  • Never nudge a figure so a year sums to 100. Harvard’s FY2019, FY2024 and FY2025 sum to exactly 101 as published, sitting on the tolerance boundary — one tidy-up flips them to failing. Materially out of tolerance is an escalation, never a quiet widening of the constant.

07Auditing what was decided for you

The whole point of proxied decisions is that they stay reversible. Four greps — and deliberately no counts beside them. Every count this table once carried had drifted by the time anyone read it (the four were 8, 4, 1 and 0; on 2026-08-29 they were 12, 28, 8 and 0). Run the grep; don’t trust a printed answer, and don’t re-add one:

GrepFinds
grep -n "\[PROXY DECISION\]" TASKS.mdEscalated rulings. Not every hit is a ruling — the tag’s own definition, task-line mentions and replay references match too, so read the hits rather than counting them.
grep -n "\[JUDGMENT CALL\]" TASKS.mdSmall calls made without escalation, each with its reasoning beside it. One hit is the tag’s own definition.
grep -n "\[HITL\]" TASKS.mdYour own recorded answers — the decisions no model was allowed to make.
grep -n "\[DISSENT\]" TASKS.mdZero — never used yet. It exists so a losing argument that turns out right is on the record.

Each ruling must carry the question, the options, both tiers’ recommendations, the article check, what was implemented, and what would justify revisiting it. If one is missing any of those, the protocol failed even if the decision was right.

The health number

Ratification rate. If the senior tier always agrees with the junior, the check is decorative and the floor is set too low. Across the five rulings so far: one ratified with additions, two where the senior refuted the junior’s premise using documents the junior never gathered, and two modified. That is a healthy spread — the tier hop is doing real work.

Five rulings are settled and should not be reopened without new evidence: Yale’s post-FY2020 coverage, Harvard’s granularity and target basis, Harvard’s undated tables, negative allocation weights, and the pool-basis rule. Each records what would justify revisiting.

08When it breaks

The task 1.6 pilot absorbed roughly seventeen infrastructure failures with zero work lost. Here is why, and what to do.

SymptomDo this
A worker dies — connection closed, or stalled Resume it, do not respawn it. Its transcript, scratch directory and any written fragments survive; a fresh agent redoes hours of work. If the same agent keeps dying on long final messages, tell it to write its report to a file first and reply in one line.
The conductor died mid-task Just run /conduct again. State is in TASKS.md and conduct/plans/. Read the plan file first — it carries per-unit status markers.
A worker blew its budget Once is normal — first-contact archival research ran about 1.6× the rubric’s estimates. Twice means the task is mis-scoped: re-decompose it, never tell the worker to try harder.
Validation fails after a merge Nothing is half-written. Workers never write inside data/; their output sits in conduct/fragments/. Fix and re-merge.
A write failed partway It rolled back — the write is one transaction. This already happened once in production with zero residue. Fix the cause and re-run.
You suspect another session is active Run the four-check block from §2. Leases are a convention, not a lock, and they live in a shared file — so check briefs and git status too.
A worker reports its own token spend Ignore it. Self-estimates came in at roughly half the metered truth, four times out of four. Trust the harness numbers only.
Does not survive

Session scratchpads. Extraction scripts, downloaded PDFs and draft rulings live there and are gone tomorrow — regenerate rather than hunt. Anything that must persist belongs in TASKS.md, data/README.md, or a committed file. That is why every ruling is quoted into the build log rather than referenced.

11Traps worth knowing

Hard-won during curation. The ones that matter most are the data traps, because no automated check catches any of them — a wrong-column read produces a plausible, cited, wrong number.

Data

  • Columns that look like returns but are not. MIT prints “Net Endowment Growth” beside its return column; growth includes gifts and spending. FY2000 reads 51.0% growth against a 55.6% return.
  • Accounting negatives. (2.0)% means −2.0%. A naive number-grab flips the sign, and nothing downstream catches it because returns are never summed. This was caught once only because the value contradicted the surrounding prose.
  • Target and actual tables sit adjacent. Identify columns by their header, never by position — and some tables run in reverse chronological order.
  • A table’s label can contradict its own document. Stanford’s pre-2016 reports head their tables “Endowment” while the same document states the universe is a broader pool. The document’s stated universe wins, not the headline.
  • The same words change meaning by era. “Total endowment funds” is a combined figure in Stanford’s modern reports and a university-only figure in older ones.
  • Annual reports contain pension-plan allocation tables. Real percentages, with targets, in the audited report — and the wrong entity entirely.

Sourcing and tooling

  • Soft-404s. Some sites return HTTP 200 with an identical error page for every year. Verify you fetched a document, not a stub — check bytes and page count, not the status code.
  • Archived captures can be truncated at HTTP 200. Check the recorded length.
  • Fetching archives: the built-in fetcher is blocked from the Internet Archive but plain curl is not. Get timestamps from the CDX index; per-URL queries succeed where wildcards fail; try both URL schemes, neither is reliably the working one.
  • PDF text: there is no poppler on this machine, and the tool the build log recommends is not actually installed — but pdfminer.six, pdfplumber and cryptography are. Extract text rather than reading table images: you get the printed digits instead of a model’s reading of them. Watch for old-style figures, which extract as glyph names.
  • Look for multi-year tables first. One Yale report page carried five fiscal years, turning twenty-one documents into five.

Process

  • Numbers can be right while the reasoning is wrong. That was every defect the pilot’s QC caught — four for four. When you read a build-log entry, read the why, not just the figure.
  • Assemble merged categories arithmetically, with a script that prints each year’s sum, rather than by hand.
  • Never spot-check a worker’s own chosen years. That is grading homework against its own answer key. Draw the sample yourself, afterwards, excluding theirs.
