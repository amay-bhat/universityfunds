**2026-07-24 — Task 1.2 (seed script) complete.**
- `scripts/seed.ts`, run by `npm run seed`. Two design decisions worth carrying forward:
  - **Validate everything, then write — or write nothing.** All files are parsed and checked before the DB module is even imported, and the script exits 1 with the full error list on any failure. The Neon HTTP driver can't do interactive multi-statement transactions, so an all-or-nothing gate *before* the first write is the only way to guarantee a bad edit can't leave the DB half-updated.
  - **Upsert on natural keys + prune.** Rows are upserted (ids stay stable across re-seeds), and any DB row whose natural key is no longer in `data/` is deleted. Without the prune, deleting a row from a seed file would silently leave it live in the DB, which contradicts "seed files are the source of truth."
