## The fragment protocol (the plan's key decision)

**Workers write nothing inside `data/`** — not even their own school file. A
worker landing `data/schools/<id>.json` early would leave the repo's
`seed:dry` red with dangling `sourceId`s until integration; under this
protocol the repo is green at every instant, an abandoned worker leaves zero
residue, and the merge is mechanical. Everything travels as fragments under
`conduct/fragments/1.6/` (shapes in COMMON.md); workers validate in a private
sandbox via `--dry-run --data-dir <scratch>/data` (verified working). Source
id prefixes are per-unit (`smc-` / `mitimco-` / `princo-`) so ids cannot
collide. `TASKS.md` is never opened by workers — build-log prose travels as a
fragment. `STATUS.html` has no fragment: the conductor re-renders it from the
ledger. Rails (`constants.ts`, `schema.ts`, `seed.ts`, `seed-validate.ts`)
are STOP-AND-REPORT, never fragments — changing a rail mid-fan-out
invalidates the other workers' in-flight validation.

## Integration lane (conductor only, serialized)

1. Pre-flight: `git status` clean; baseline counts still 33/203/44/10-warn
   (if moved, another session has been here — stop and reconcile).
2. Merge order: sources first (stanford → mit → princeton), verify id
   uniqueness + prefixes; then school files; **one school at a time**, with
   `seed:dry` after each so a failure attributes to one worker with no
   bisection.
3. Full gate: `seed:dry` → `npm run seed:verify` (must stay at full pass
   count — it is how a rail edit by a worker is detected) → `npm run lint` →
   `npm run build` → `npm run seed` (the only --write, once, after sampling
   passes) → `seed:dry` again (idempotence).
4. Independent checks beyond the validator: per-school-year sums recomputed
   to 2dp (±0.5pp goes on the sample list even though ±1.0 passes); row-count
   arithmetic per basis regime (a dropped small line item passes the sum rule
   — category cardinality per year catches it); baseline count diffs must
   match workers' claimed counts exactly (mismatch = K1/K2 event); warning-set
   diff (no covered series becomes uncovered; a new `global_equity` warning
   must correspond to a school genuinely publishing unsplit equity); every
   negative-`pct` warning read against its source — the project's first
   stored negative activates display obligations in tasks 3.2/4.2/6.1, which
   this lane carries into the ledger.
5. Docs: three README sections inserted after Harvard's, before the
   granularity rule; README inventory table updated; TASKS.md checked off
   only if all three schools land (else marked partial in house style);
   build-log entry merged from fragments + integration/sampling notes;
   STATUS re-rendered. Commits: one per school + one docs commit (so a school
   failing later sampling reverts alone). Push is separate and explicit — it
   deploys.
6. Gate after 1.6: frontier moves to 1.7, then **CHECKPOINT A** — a human
   review point, never escalatable.

## Sampling plan (1.6.QC) — sample where the machine is blind

1. MIT's gap finding: **100%, not a sample** — re-walk the trail + fresh-context
   adversarial refuter ("find the table this report says does not exist").
2. One random year per school, drawn by the conductor after delivery,
   **excluding the worker's own spot-check years** (never grade homework
   against its own answer key); primary document re-fetched, every figure
   compared.
3. Every regime-boundary year (first/last of each basis run; every label
   change) — both prior curations prove boundaries are where errors live.
4. Every negative `pct` and every year outside ±0.5pp — read the prose
   (the `(2.0)%` sign-flip precedent is invisible to all sums).
5. Every `sourceLabel` on a merged category — the entire audit trail for
   normalization.
6. Every Princeton dating claim of evidence class (b) — method validated
   against a dated disclosure first, overlay-free classes only.

A failed sample re-routes that school up a tier and it does not land; two of
three failing the same way = systematic → re-route the group + routing-rubric
note.
