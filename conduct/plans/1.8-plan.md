## 0. What this task is, and what it is not

The audit found **74 sites** — 8 high, 29 medium, 37 low — across 24 files. It
found **no defect in any stored figure, in the validator's behaviour, or in the
build**. Every finding is a document, a log entry, or a test's discriminating
power. Article 10 and K6 therefore bound this task hard: **do not change data.**
`verify.sh`'s GROUND TRUTH block exists to catch a violation and must stay green
at every instant.

The audit's own root-cause sentence is this plan's design spec:

> `TASKS.md` earns its source-of-truth status — its own counts reconcile against
> the files — and the renderings drifted away from it.

`TASKS.md` is true because it is prose about *work*. The renderings are false
because they are prose about *numbers* that nothing recomputes. That is a
missing rail, not 74 independent mistakes.

## 3. The fragment protocol (the plan's key decision)

Extended from 1.6's additive-block form to **per-site anchor-text edit
fragments**, because this task edits existing prose rather than appending new
blocks.

**No worker writes in any target file.** Ownership is
`conduct/fragments/1.8/<unit>/`, one `<finding-id>.fragment.md` per site:

```
finding: A-28
file: STATUS.html
anchor: <verbatim current text, ≥1 line, must match exactly once>
replace: <verbatim replacement>
derivation: <the command whose output justifies every number in `replace`>
refuted-check: <the R-id checked, or "none">
```

The conductor applies fragments with `apply-patches.py --check` (anchor matches
exactly once, ownership respected) then `--apply`. Rationale, unchanged from
1.6: the repo is green at every instant, an abandoned worker leaves zero residue,
and the merge is mechanical.

> **The bootstrap, fixed after gate 2.** `apply-patches.py` is the tool that
> applies fragments, so it cannot itself arrive *as* a fragment applied by the
> merge that needs it — and §3's shape (a once-matching verbatim `anchor`, a
> `<finding-id>.fragment.md` name) cannot express four **new** files from a unit
> that owns **zero** findings. So: **1.8.R runs in W0, inside the conductor's
> pre-flight, and delivers its four files directly to their final paths** — not as
> fragments. R is the single exemption, and it is safe precisely because R
> *creates* files and edits nothing that exists (`git diff --stat` against every
> pre-existing path stays empty for R's commit). §7 rule 2 (anchor fidelity)
> therefore does not apply to R; §7 rule 1's 100% sample of R is its mutation
> proof instead. Every other unit emits fragments and nothing else.

**Rails are STOP-AND-REPORT, never fragments** — `constants.ts`, `schema.ts`,
`seed.ts`, `seed-validate.ts`. 1.8.V may edit `verify-seed-validator.ts` only;
if a test case cannot be written without changing validator *behaviour*, stop.

**`TASKS.md` is never opened by a worker.** Build-log prose travels as a
fragment. `CONSTITUTION.md` and `kernel.md` are never opened by anyone —
`git diff --stat HEAD -- CONSTITUTION.md .claude/skills/escalate/references/kernel.md`
must be **empty at every commit**. Gate 2 found this guard enforced by nothing, so
it is now **a step in the §6 gate and a limb of K-A**, not prose. And because
1.8.S's write scope is the glob `.claude/skills/**`, which *contains* `kernel.md`:
**`kernel.md` is carved out of S's scope explicitly** — S may write
`escalate/SKILL.md`, `brief.md` (descriptive content only) and
`conduct/**`, never `kernel.md`.

**R3 · THE GOVERNING RULE: a fact that moves may not be written as a value.**

> **This rule is the plan's structural correction, adopted after the second
> acceptance gate.** The first two drafts wrote it for *volatile external* facts
> only and then pinned *internal* facts to values — including facts **this task
> itself changes**. Gate 2 caught the consequence: §4 pinned "total logged
> `[PROXY DECISION]` rulings" at **5** while §6 step 5 orders two new rulings
> logged, making the true end state **7**. The rail would have shipped a
> machine-authoritative assertion that the correct value is wrong, and a Sonnet
> unit forbidden from deriving numbers would have written "five" into a document
> while the ledger held seven. **That is this plan's own §0 root-cause sentence,
> committed by the remediation, with a linter behind it.** One rule prevents the
> whole class.

Every fact in the registry is classified, and the classification decides the
assertion shape:

| Class | Definition | Assertion the rail makes |
|---|---|---|
| **VOLATILE** | changes without anyone touching the repo — `npm audit` (registry-live), `git rev-list --count origin/main..HEAD` | *"this document hard-codes no number here"* + the derivation command in prose |
| **MUTATED** | **this task changes it** — ruling counts, log-tag counts, task/phase counts, validator case counts | **the REGISTRY stores no integer; the LINTER asserts `rendered value == derivation output`.** The document still renders a number — it must, to read as English and to render a meter width — but no constant is ever hand-copied, and the value is re-derived at §6 step 7 |
| **STABLE** | this task does not change it and nothing external moves it — the escalation *attribution*, the undated-table count, coverage spans | a canonical value **plus** its derivation command, pinned and equality-checked across member sites |

**Only STABLE facts get a pinned value *in the registry*.** R3 governs what the
**registry pins**, not what the **document renders** — a distinction gate 3 found
missing, and without which 1.8.T received two contradictory orders for the same six
lines (write 12/26 and 88%, and write no number). The resolution the plan already
implies at §6 step 7 (*"re-derive every asserted count in the LAST integration
step"*) is now explicit: **the site renders the re-derived value; the registry holds
only the derivation; the linter compares the two.** A worker never invents or
hand-copies a number — it runs the derivation its brief names and writes what comes
back, which is also what lets a Sonnet unit comply with R2's no-deriving rule.

## 12. Where fan-out does not pay — stated plainly

`conduct/SKILL.md:104-106` forbids fan-out theatre. Honestly:

- **The ledger (5 findings) gets zero worker units.** Workers never open
  `TASKS.md`; ledger editing is structurally conductor-only.

isolation** over eight distinct artifacts — not speed.
